# 選ばれる理由AI

顧客に選ばれるための「顧客がAIにする質問・正確な回答・一次情報・顧客接点・実行」を、質問への回答を通じて整理するローカル保存型の戦略ワークベンチです。

## できること

- 初めての人向けに16問だけを、日常語で順に答える。分からない質問は「あとで答える」で飛ばせる
- 最初は「お店・会社は何をしているか」「お客さんの困りごと」「お客さんがAIや検索に何と聞きそうか」から始め、専門的な補足は必要なときだけ開ける
- 企業のホームページURLを入力するだけで、サイトの事業内容・商品・サービス・特徴を自動で取得・解析し、質問1（お店・会社は何をしていますか？）の入力欄に要約反映できる
- 回答するたびに、システムが「ここまで、こう理解しています」と言い直し、AI・検索で使われそうな質問や、公式サイトに載せる事実の下書きを提案する。下書きは必ず実際の顧客の言葉と事実に直して使う
- 文章で答える質問には「話して入力」を表示する。対応ブラウザでは話した内容を文字にして入力でき、認識結果は必ず見直してから保存できる
- ターゲットを「顧客がAIに何と質問する人か」と定義し、複数のAI質問候補を、質問の実在性、正確に答えられるか、事業価値、AI参照情報、選ばれる答えの余白で根拠とともに比較する
- AI検索を設計全体の最優先（90%）に置き、質問 → 正確な回答 → 公式の一次情報・FAQ・条件・更新日 → 確認担当者の対応を作る
- 業種と販売・利用の形を起点に、AI質問のつくり方、確認する事実、回答を支える情報、補強媒体、公開前の注意を宿泊・飲食・EC・BtoB・専門サービスなどに合わせて切り替える
- Google検索、SNS、クチコミ、OTA、チラシ、地域接点などを、AI検索の答えを補強・確認・予約購入につなげ・反応を検証する役割として設計する
- 回答状況から、次に価値が高い三つの行動を提示し、仮説を小さく検証できるようにする
- 事実・仮説・未確認事項を分け、未検証の主張を外部向けの断定表現にしない
- 対外表現に必要な条件、例外、承認、販売後のフィードバックを確認する
- 戦略ブリーフと、生成AIへ安全に引き継ぐための対話プロンプトを出力する

## アプリが読む実務知識データ

送っていただいた書籍画像の範囲（p.229〜262）は、アプリが読む独自要約の知識カードとして、次のファイルに保存しています。

- `dist/data/selected-reason-knowledge.json`

このファイルには、34ページすべてを対応づけた22枚の知識カード（章・要点・判断基準・質問・実行・注意点）が入っています。画面は、回答中の質問に関係するカードを読み、画面の補足、戦略ブリーフ、AIへの引継ぎプロンプトに反映します。公開後は `/data/selected-reason-knowledge.json` でも確認できます。

書籍のページ画像や原文そのものは、GitHub や Netlify に転載・公開していません。代わりに、実務で使う判断基準として独自の言葉に整理しています。

## 大切な制約

この初期版は、外部の生成AI APIへデータを送らず、ブラウザ内で質問・整理・安全チェックを行います。生成AIとのリアルタイム対話を追加するには、別途、承認済みのAPI接続とサーバー側の秘密情報設定が必要です。

音声入力はブラウザの音声認識機能を利用します。対応状況や音声データの扱いは、利用するブラウザとその設定に従います。マイクの許可が必要で、認識された文字は利用者が確認・修正してから使う前提です。

外部AIの回答採用・表示・順位を保証したり、操作できると示唆したりするものではありません。顧客自身も確認できる公式の一次情報・FAQ・条件・更新日を整え、AIにも人にも正確に答えられる状態をつくるための設計ツールです。

顧客の発言・実績・数値・比較・保証は創作せず、公開前には人が事実、法令、提供能力、利用許諾を確認してください。

## Netlify への公開

このプロジェクトは静的サイトとして構成されており、`netlify.toml` は公開ディレクトリを `dist` に指定しています。GitHub に接続した後、Netlify でこのリポジトリを選択すれば、追加のビルドコマンドなしでデプロイできます。
